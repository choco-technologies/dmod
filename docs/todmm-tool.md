# todmm - DMM Manifest Generator

## Overview

**todmm** is a command-line tool that scans a folder of DMF/DMFC module files and generates a `.dmm` manifest file. Each entry in the manifest is prefixed with a configurable base URL, making it easy to publish a directory of modules to a remote registry.

It also supports a **zip mode** (`--zip`) where it scans for `.zip` release packages (as generated in `build/packages/` when building in `DMOD_MODULE` mode) and generates a manifest entry for each package.

## Usage

```bash
todmm <folder> <base_url> [-o output.dmm] [--zip]
```

### Arguments

| Argument | Required | Description |
|----------|----------|-------------|
| `<folder>` | Yes | Path to the folder containing `.dmf` / `.dmfc` module files (or `.zip` packages in zip mode) |
| `<base_url>` | Yes | Base URL or path prepended to each module file entry |

### Options

| Option | Description |
|--------|-------------|
| `-h`, `--help` | Print help message |
| `-v`, `--version` | Print version information |
| `-o <file>` | Output manifest file path (default: `manifest.dmm`) |
| `-z`, `--zip` | Scan for `.zip` release packages instead of `.dmf` / `.dmfc` files |

## Examples

```bash
# Generate manifest.dmm from all modules in ./dmf
todmm ./dmf https://registry.example.com/modules

# Specify a custom output file with -o
todmm ./dmf https://registry.example.com/modules -o output.dmm

# Base URL ending with '/' - no extra separator is added
todmm ./dmf https://registry.example.com/modules/ -o manifest.dmm

# Generate manifest from zip release packages
todmm ./build/packages https://releases.example.com/packages --zip
```

## Generated File Format

The tool generates a `.dmm` manifest file:

```dmm
# DMOD Manifest
# Generated by todmm from folder: ./dmf
# Base URL: https://registry.example.com/modules

kernel@1.0 https://registry.example.com/modules/kernel.dmf
driver@2.3.1 https://registry.example.com/modules/driver.dmf
app https://registry.example.com/modules/app.dmf
```

Each entry has the form `module_name@version url`. If the module header has no version, the `@version` part is omitted.

In **zip mode**, the module name is derived from the filename (without the `.zip` extension) and no version is included:

```dmm
# DMOD Manifest
# Generated by todmm from folder: ./build/packages
# Base URL: https://releases.example.com/packages

kernel https://releases.example.com/packages/kernel.zip
driver https://releases.example.com/packages/driver.zip
app https://releases.example.com/packages/app.zip
```

## How It Works

1. Opens the specified folder using `Dmod_OpenDir()`
2. Iterates over directory entries, filtering for `.dmf` and `.dmfc` files (or `.zip` files in zip mode)
3. For each module file, reads its header using `Dmod_ReadModuleHeader()` (in crossplatform mode) to obtain the module name and version. In zip mode, the module name is derived from the filename instead.
4. Constructs the download URL by joining `base_url` and the filename (adds `/` separator unless the base URL already ends with one)
5. Writes a manifest entry to the output `.dmm` file

## Integration with dmf-get

The generated `.dmm` manifest can be used directly with `dmf-get` to download modules:

```bash
# Generate manifest from local build output
todmm ./build/dmf https://myserver.example.com/modules -o manifest.dmm

# Use the manifest with dmf-get
dmf-get -m manifest.dmm mymodule@1.0
```
