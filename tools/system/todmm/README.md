# todmm - DMM Manifest Generator

## Overview

The `todmm` tool scans a folder of DMF (DMOD Module Files) and generates a
`manifest.dmm` file listing every module found in the folder. Each entry in the
manifest is prefixed with a configurable base URL, making it easy to publish a
directory of modules to a remote registry.

## Usage

```bash
todmm <folder> <base_url> [output.dmm]
```

### Arguments

- `<folder>` - Path to the folder containing `.dmf` / `.dmfc` module files (required)
- `<base_url>` - Base URL or path prepended to each module entry (required)
- `[output.dmm]` - Output manifest file path (optional, defaults to `manifest.dmm`)

### Options

- `-h, --help` - Print help message
- `-v, --version` - Print version information

## Examples

```bash
# Generate manifest.dmm from all modules in ./dmf
todmm ./dmf https://registry.example.com/modules

# Specify a custom output file
todmm ./dmf https://registry.example.com/modules output.dmm

# Base URL ending with '/' - no extra separator is added
todmm ./dmf https://registry.example.com/modules/ manifest.dmm
```

## Generated File Format

The tool generates a `.dmm` manifest file with the following format:

```dmm
# DMOD Manifest
# Generated by todmm from folder: ./dmf
# Base URL: https://registry.example.com/modules

kernel@1.0 https://registry.example.com/modules/kernel.dmf
driver@2.3.1 https://registry.example.com/modules/driver.dmf
app https://registry.example.com/modules/app.dmf
```

Each entry has the form `module_name@version url`. If the module has no version
in its header, the `@version` part is omitted.

## How It Works

1. Opens the specified folder using `Dmod_OpenDir()`
2. Iterates over directory entries, filtering for `.dmf` and `.dmfc` files
3. For each module file, reads its header using `Dmod_ReadModuleHeader()` to
   obtain the module name and version
4. Constructs the download URL by joining `base_url` and the filename
5. Writes a manifest entry to the output `.dmm` file
